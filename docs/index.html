Predicting Content Decline for Refresh Prioritization

FlyRank ML Internship Capstone Lane 2: Refresh / Content Opportunity Scoring

Shamique Khan · August 2025
GitHub Repository · Data Source: FlyRank
Abstract Content teams have limited capacity to review pages for refresh. This work builds a decision-support model that ranks pages by estimated decline risk using observable search signals. On a 30K-page starter dataset (32 clients, 90-day snapshot), a Random Forest model achieved 96% Precision@50 under a random split, dropping to 74.4% under an honest client-grouped split — still directionally above the 58% rule-based baseline. The model identifies staleness, visibility, and CTR gap as key signals. Findings are associative, not causal; refresh may not reverse decline. The output is a ranked action playbook with human-review checklists, not an automation.

1. Introduction / Problem

FlyRank operates a content intelligence platform that helps clients maintain search visibility across thousands of pages. A core operational problem: content teams have limited reviewer capacity and need a data-driven way to decide which pages to review first for refresh, metadata updates, or consolidation.

The current workflow relies on hand-coded rules (e.g., "flag pages not updated in 180 days with >1000 impressions"). These rules are transparent but rigid — they cannot capture interactions between signals like content age, position, CTR, engagement, and competition level. Machine learning can learn these interactions from historical data and produce a ranked queue that concentrates actually-declining pages at the top.

This capstone addresses the Refresh / Content Opportunity Scoring lane (Lane 2): given observable page-level signals from Google Search Console and Google Analytics 4, can we predict which pages are currently declining so reviewers can prioritize their limited capacity? The output is not an automated action but a prioritization aid — a flashlight for human decision-makers.

2. Data

Source

Starter dataset: content_refresh_anonymized.csv — 30,000 rows × 44 columns, one row per pseudonymized content item across 32 clients. Trailing 90-day aggregated metrics from GSC and GA4.

Warehouse (not used in this capstone): FlyRank internship warehouse on Hugging Face (hf://datasets/FlyRank/internship-warehouse) — 78.8M daily rows across ~17 months (Jan 2025 – Jun 2026), 57 brands, partitioned by month. This capstone uses only the starter slice; the warehouse enables time-aware validation for future work.

Exclusions & Gotchas

  • Label leakage: trend_direction and trend_pct are NEVER features — they directly encode the target.
  • Rate columns: ctr, engagement_rate, scroll_rate, ai_traffic_pct are ×100 percentages.
  • Missingness: Follows content_type; blind fillna(0) injects category signal. Added has_* flags instead.
  • IDs: content_id, client_id are pseudonyms — grouping/splitting only, never features.

3. Methodology

Task Framing

Binary classification: predict target = 1 (page declining now). Output probability → ranked queue. Primary metric: Precision@50 (of top 50 flagged pages, how many are actually declining?). Matches reviewer capacity (~50 pages/review cycle).

Features (17 numeric + 10 categorical → 42 after one-hot)

  • Numeric: search_volume, competition, cpc, word_count, char_count, impressions_90d, clicks_90d, ctr, avg_position, sessions_90d, engaged_sessions_90d, days_since_last_update, content_age_days, scroll_rate, engagement_rate, ai_traffic_pct, log-transformed impressions/clicks/sessions
  • Categorical: competition_level, content_type, main_intent, age_tier, freshness_tier, word_count_tier, char_count_tier, impression_tier, position_tier

Baseline

Rule-based score: Staleness (35%) + Visibility (35%) + CTR Gap (30%). Reason codes: HIGH_OPPORTUNITY, STALE_VISIBLE, CTR_GAP, MONITOR. Baseline Precision@50 = 58% (base rate = 54.2%).

Models

  1. Logistic Regression (readable, calibrated probabilities) — P@50 = 74%
  2. Random Forest (300 trees, max_depth=10, min_samples_leaf=20) — P@50 = 96% (random) / 74.4% (grouped)

Complexity must earn its keep. Random Forest meaningfully beats LR on grouped split.

Validation Design

  • Random split (Week-5): 80/20 stratified, seed=42. Overestimates generalization.
  • Grouped split (Week-6, honest): 5-fold GroupKFold by client_id. Tests generalization to unseen clients.
  • Time-aware: Not possible on starter slice (single snapshot). Warehouse enables this.

Leakage Checks

  • Train-without test on trend_pct: AUC jumps from 0.754 → 1.000 (importance rank #1, 0.843). Confirms correct exclusion.
  • Clean model max feature importance = 0.199 (impressions_90d). No single feature dominates.
  • Population selection: no filtering on outcome-window info (label is proxy, not future).

Error Analysis (Grouped Split)

  • False Positives: High-impression pages with recent updates but moderate position/CTR — model is "early" (flags before decline materializes).
  • False Negatives: Low-impression declining pages (model deprioritizes — matches business logic) and fresh pages with sudden drops (no staleness signal; needs trend features).
  • Error by impression tier: Higher error rates in low-impression tiers (sparse signal).

5. Limitations & Honest Framing

This work observes associations in one snapshot. It does not establish causation.
LimitExplanation
Single snapshotOne 90-day window, 30K pages, 32 clients. No temporal generalization tested.
Proxy labelTarget = current trend (last-30d vs prev-30d), not future decline. A "declining now" page may recover naturally.
Grouped split dropP@50 drops 96% → 74.4%. Model memorizes client patterns; generalization to new clients unproven.
No causal claimRefreshing a flagged page may not reverse decline. Model identifies correlates, not levers.
Feature gapsNo trend features (impression_trend, ctr_trend), no query-level signals, no backlinks.
Starter dataset only30K rows is a sample. Warehouse has 79M rows across 57 brands — patterns may differ.
No cost modelRefresh effort vs. expected uplift not quantified. High-impression pages may be expensive to refresh.
Client heterogeneity32 clients with 3–7008 rows each. Model may overfit large clients, underfit small ones.

Claim ladder compliance: Every conclusion uses observed, measured, directional, decision-support language. No "proves," "causes," "will increase," or "algorithm rewards" phrasing.

Human Review Checklist (Per Page)

  1. Business context — strategic importance?
  2. Competitive landscape — SERP changes?
  3. Content quality — actually thin/outdated?
  4. Refresh cost — ROI viable?
  5. Cannibalization — multiple pages same intent?
  6. Technical health — indexable, mobile, fast?
  7. Historical pattern — prior refreshes worked?

No-Go Automation List

  • Auto-refresh content (quality depth beats arbitrary length)
  • Auto-rewrite titles/metas (needs intent understanding)
  • Auto-redirect or delete pages (strategic call)
  • Allocate budget solely on score (high score ≠ high ROI)
  • Trigger recrawl automatically (budget finite)
  • Replace human QA (FP rate ~20% in grouped split)
  • Generalize to new clients/verticals without re-validation
